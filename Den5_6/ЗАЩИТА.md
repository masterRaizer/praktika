# Защита дней 5–6: как запустить

Нужно только то, что относится к дням 5–6: база «Киноточка» и приложение `Kinotochka`.
Остальные папки репозитория (Forecast, Den1, UML_Den1–4, DE_Obuv) для защиты не нужны.

## Промпт для агента (Claude Code на компьютере для защиты)

Скопируйте текст ниже целиком и отправьте агенту, открытому на компьютере с Windows.

```text
Подготовь к защите и запусти ТОЛЬКО дни 5–6 учебной практики — приложение «Киноточка» с базой данных
MS SQL Server. Ничего другого из репозитория (Forecast, Den1, UML_Den1–4, DE_Obuv) не собирай и не запускай.

Источник: репозиторий https://github.com/masterRaizer/praktika, ветка claude/elegant-ptolemy-c1gknu,
папка Den5_6. Готовые файлы есть в релизе с тегом den5-6-2026-11-21 (Kinotochka_exe.zip, Den5_6_src.zip,
01_create.sql, 02_data.sql). Если git есть — склонируй только эту ветку (git clone --branch
claude/elegant-ptolemy-c1gknu --single-branch https://github.com/masterRaizer/praktika.git), иначе скачай
файлы релиза. Работай в отдельной папке, например C:\Praktika_Den5_6.

Шаги:
1. Найди SQL Server на этом компьютере: выполни `sqllocaldb info` (LocalDB из Visual Studio) и
   проверь службы MSSQL$SQLEXPRESS / MSSQLSERVER (`Get-Service *SQL*`). Выбери сервер:
   (localdb)\MSSQLLocalDB, если LocalDB есть (при необходимости `sqllocaldb start MSSQLLocalDB`),
   иначе .\SQLEXPRESS или localhost. Если SQL Server нет вовсе — остановись и скажи мне,
   что установить (SQL Server Express или LocalDB), ничего не устанавливай без моего согласия.
2. Создай базу «Киноточка»: выполни по порядку Den5_6\db\01_create.sql и Den5_6\db\02_data.sql через
   sqlcmd с ключом -f 65001 (файлы в UTF-8, имена таблиц и столбцов русские), например:
   sqlcmd -S "(localdb)\MSSQLLocalDB" -E -b -f 65001 -i Den5_6\db\01_create.sql
   sqlcmd -S "(localdb)\MSSQLLocalDB" -E -b -f 65001 -i Den5_6\db\02_data.sql
   Если sqlcmd нет — открой эти файлы в SQL Server Management Studio и выполни (F5), или попроси меня.
   Проверь: SELECT COUNT(*) FROM Киноточка.dbo.Фильмы должно вернуть 7, Пользователи — 8.
3. Получи программу: если есть Visual Studio / MSBuild — собери Den5_6\src\Kinotochka.sln в конфигурации
   Release (msbuild Den5_6\src\Kinotochka.sln /p:Configuration=Release); иначе распакуй Kinotochka_exe.zip
   из релиза. Папки Fonts и Resources должны лежать рядом с Kinotochka.exe.
4. Если сервер НЕ (localdb)\MSSQLLocalDB — в Kinotochka.exe.config (и Kinotochka.Tests.exe.config)
   замени Data Source=(localdb)\MSSQLLocalDB на выбранный сервер. Больше ничего в конфигурации не меняй.
5. Запусти проверки: Kinotochka.Tests.exe (из src\Kinotochka.Tests\bin\Release, если собирал сам).
   Должно быть «Итого проверок: 58, пройдено: 58». Таблица результатов на русском появится рядом
   (Результаты_тестирования.md и .csv). Если какие-то проверки не прошли — покажи мне их строки и причину,
   ничего в коде не исправляй без моего согласия.
6. После проверок пересоздай базу ещё раз (шаг 2), чтобы данные были в исходном состоянии для показа.
7. Запусти Kinotochka.exe и оставь окно входа открытым. Не входи в систему сам.
8. Выведи мне коротко: какой сервер используется, результат проверок (сколько пройдено из 58),
   путь к Kinotochka.exe и к отчёту Den5_6\Отчёт_День5-6.pdf, и таблицу учётных записей для показа:
   admin@kinotochka.ru / 123456 — администратор; cashier1@kinotochka.ru / 123456 — кассир;
   ivanov@example.com / 123456 — зритель; morozov@example.com / 123456 — заблокирован (вход запрещён).
```

## Сценарий показа преподавателю (5–7 минут)

| № | Что показать | Как | Что проверяется (задание) |
|---|---|---|---|
| 1 | Подключение к базе | форма входа: зелёная строка «База данных подключена» | день 5, задания 2 и 4 |
| 2 | Неуспешный вход | admin@kinotochka.ru, пароль 654321 → «Неверная почта или пароль. Осталось попыток: 2» | день 6, задания 1 и 4 |
| 3 | Заблокированный пользователь | morozov@example.com / 123456 → «Учётная запись заблокирована» | день 6, задание 1 |
| 4 | Регистрация | «Регистрация» → разные пароли → ошибка; правильно → «Учётная запись создана» | день 6, задание 1 |
| 5 | Хеш пароля | в SSMS: `SELECT ЭлПочта, ХешПароля FROM Киноточка.dbo.Пользователи` — паролей в открытом виде нет | день 6, задание 1 |
| 6 | Успешный вход и навигация | admin@kinotochka.ru / 123456 → разделы в боковой панели | день 5, задания 3 и 4 |
| 7 | Поиск | Фильмы → «звёзд» → Найти | день 6, задание 2 |
| 8 | Пустые и неверные поля | Фильмы → Добавить → Сохранить пустую форму; длительность 700 | день 6, задания 1 и 3 |
| 9 | Добавление и изменение | добавить фильм, двойной щелчок по строке → изменить | день 6, задание 2 |
| 10 | Удаление с проверкой целостности | удалить «Звёздный маршрут» → запрет (есть сеансы); удалить новый фильм → подтверждение | день 6, задание 2 |
| 11 | Роли | выйти → войти как ivanov@example.com → только «Мои заказы», нет кнопок изменения | день 6, задание 2 |
| 12 | Недоступность базы | «Подключение» → сервер `nosuchserver` → «Проверить» → понятное сообщение, «Подробнее» — номер ошибки без пароля | день 6, задания 3 и 4 |

После показа пункта 12 верните сервер: «Подключение» → `(localdb)\MSSQLLocalDB` → «Сохранить».

## Частые вопросы преподавателя

| Вопрос | Ответ |
|---|---|
| Где разделены интерфейс, логика и данные? | папки `Forms`, `Logic`, `Data`; формы вызывают службы `Logic`, те — репозитории `Data` (рисунок «Структура решения») |
| Как защищены запросы от SQL-инъекций? | все значения передаются параметрами `SqlParameter` (`Db.Text`, `Db.Int`…), строки SQL с вводом пользователя не склеиваются; проверка № 41 |
| Как закрывается соединение? | `using (SqlConnection c = Db.Open())` — закрывается всегда, даже при ошибке |
| Как хранится пароль? | `PBKDF2$100000$соль$хеш` (SHA-256, соль 16 байт у каждого пользователя), класс `PasswordHasher` |
| Что будет при удалении связанных данных? | программа считает связанные записи и запрещает удаление с объяснением; в обход программы удаление отклонит внешний ключ базы (ошибка 547) |
| Где технические детали ошибок? | кнопка «Подробнее» и файл `%LOCALAPPDATA%\Kinotochka\errors.log`; пароли маскируются (`Password=***`) |
